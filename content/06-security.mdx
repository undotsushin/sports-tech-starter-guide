### パスワード管理ツール

**簡単に言うと**: すべてのパスワードを安全に保存してくれるツール

**主なパスワード管理ツール**:

1. **1Password**
   - 料金: 月400円
   - 対応: Windows/Mac/iOS/Android
   - 特徴: 使いやすさNo.1
   - 用途: 個人・ビジネス

2. **Bitwarden**
   - 料金: 無料（有料版は月140円）
   - 対応: すべてのOS
   - 特徴: オープンソース
   - 用途: 個人

3. **LastPass**
   - 料金: 無料（有料版は月300円）
   - 対応: すべてのOS
   - 特徴: 有名で実績がある
   - 用途: 個人

**メリット**:
- すべてのパスワードを記憶不要
- 自動で強いパスワードを生成
- 自動入力で楽
- 複数デバイスで同期

**使い方**:
![パスワード管理ツールの使い方](/images/security/password-manager-flow.png)

**実務での会話例**:
- 「パスワード管理ツールを導入して、全員に強いパスワードを使わせましょう」
- 「1Passwordなら、チーム全体でパスワードを共有できます」

### 二要素認証（2FA）

**簡単に言うと**: パスワードに加えて、もう1つの認証を追加する方法

**仕組み**:
![二要素認証の仕組み](/images/security/two-factor-auth.png)

**二要素認証の種類**:

1. **SMS認証**
   - 電話番号に6桁の数字が届く
   - 手軽だが、SIMスワップ攻撃のリスク
   - セキュリティ: 中

2. **認証アプリ（Google Authenticator等）**
   - アプリに6桁の数字が表示される
   - SMSより安全
   - セキュリティ: 高

3. **物理キー（YubiKey等）**
   - USBキーを挿してログイン
   - 最も安全
   - セキュリティ: 最高

**必ず二要素認証を設定すべきサービス**:
![二要素認証を設定すべきサービス](/images/security/2fa-services.png)

**実務での会話例**:
- 「AWSアカウントには必ず二要素認証を設定してください」
- 「パスワードだけでは不十分です。二要素認証を有効化しましょう」

## 6.2 個人情報保護

**簡単に言うと**: 個人の情報を適切に扱い、漏洩させないこと

### 個人情報とは

**定義**:
- 特定の個人を識別できる情報
- 氏名、住所、電話番号、メールアドレスなど

**個人情報の例**:
![個人情報の例](/images/security/personal-info-examples.png)

### 個人情報保護法（日本）

**簡単に言うと**: 日本で個人情報を扱う際のルール

**対象**:
- 日本国内で個人情報を扱うすべての事業者
- 5,000人以上の個人情報を扱う場合、個人情報保護委員会への届出が必要

2. **同意の取得**
![同意の取得](/images/security/consent-good-bad.png)

3. **安全管理**
![安全管理の必須対策](/images/security/security-measures.png)

4. **第三者提供の制限**
![第三者提供の制限](/images/security/third-party-good-bad.png)

5. **開示請求への対応**
![開示請求への対応](/images/security/disclosure-request.png)

**プライバシーポリシーの必須項目**:
![プライバシーポリシーの必須項目](/images/security/privacy-policy-checklist.png)

**実務での会話例**:

- 「パスワードは必ず暗号化して保存してください。平文はNG です」
- 「退会したユーザーの情報は、すぐに削除する必要があります」

### SQLインジェクション

**簡単に言うと**: Webサイトの入力欄から、データベースを不正に操作する攻撃

**攻撃の仕組み**:
```
通常のログイン
ユーザー名: tanaka
パスワード: pass123

SQL: SELECT * FROM users WHERE name='tanaka' AND password='pass123'
→ 正常にログイン

SQLインジェクション攻撃
ユーザー名: admin' OR '1'='1
パスワード: （空欄）

SQL: SELECT * FROM users WHERE name='admin' OR '1'='1' AND password=''
→ '1'='1'は常に真なので、パスワードなしでログインできる
```

**被害**:
![SQLインジェクションでできること](/images/security/sqli-impact.png)

**実際の被害事例**:
![SQLインジェクション被害事例](/images/security/sqli-cases.png)

**対策**:
![SQLインジェクション対策チェックリスト](/images/security/sqli-checklist.png)

**実務での会話例**:
- 「SQLインジェクション対策として、プリペアドステートメントを使ってください」
- 「入力値は必ずサニタイズしてください」

### XSS（クロスサイトスクリプティング）

**簡単に言うと**: Webサイトに悪意のあるスクリプトを埋め込む攻撃

**攻撃の仕組み**:
```
掲示板への投稿例

通常の投稿:
「こんにちは」
→ 画面に「こんにちは」と表示

XSS攻撃:
「<script>document.cookie を攻撃者に送信</script>」
→ このスクリプトが実行され、Cookieが盗まれる
```

**被害**:
![XSSでできること](/images/security/xss-impact.png)

**対策**:
```
開発側の対策
□ 入力値のエスケープ処理
□ Content Security Policy (CSP)の設定
□ HTTPOnly属性のCookie
□ 入力値のバリデーション

例: エスケープ処理
入力: <script>alert('XSS')</script>
出力: &lt;script&gt;alert('XSS')&lt;/script&gt;
→ スクリプトとして実行されず、文字として表示
```

**実務での会話例**:
- 「ユーザー入力は必ずエスケープしてください」
- 「CSPヘッダーを設定して、XSS対策を強化しましょう」

### CSRF（クロスサイトリクエストフォージェリ）

**簡単に言うと**: ユーザーが意図しない操作を、勝手に実行させる攻撃

**攻撃の仕組み**:
![CSRF攻撃の流れ](/images/security/csrf-flow.png)

**対策**:
```
開発側の対策
□ CSRFトークンの利用
□ Referrerチェック
□ 重要な操作は再認証を要求

CSRFトークンの仕組み:
1. フォーム表示時にランダムな文字列（トークン）を生成
2. フォーム送信時にトークンを一緒に送る
3. サーバーでトークンが正しいか確認
→ 攻撃者のサイトからは正しいトークンを送れない
```

**実務での会話例**:
- 「重要な操作には必ずCSRFトークンを使ってください」
- 「送金など重要な操作では、パスワードの再入力を求めましょう」
